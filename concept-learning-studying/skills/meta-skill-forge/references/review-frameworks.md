# 리뷰 프레임워크

이 문서는 메타 스킬 포지의 **단계 6: 검증** 시작 전에 반드시 읽는다.

---

## 프레임워크 1: 첫째 원리 점검 (First Principles)

모든 구성 요소를 기본 요구사항까지 분해한 뒤,
각 요소가 존재할 자격이 있는지 검증한다.

### 실행 순서

1. 스킬의 모든 구성 요소를 나열한다 (섹션, 규칙, 참조 파일, 단계 등)
2. 각 요소에 대해 묻는다:
   - "이것을 제거하면 결과물의 품질이 떨어지는가?"
   - "떨어진다면, 구체적으로 어떻게?"
   - "이것을 더 단순한 것으로 대체할 수 있는가?"
3. 답이 "아니오"인 요소는 제거한다
4. 두 곳 이상에 같은 정보가 있으면 하나로 합친다

### 판단 기준

- 제거해도 결과물이 같다 → 삭제
- 두 요소를 합쳐도 기능이 유지된다 → 합친다
- 복잡도를 추가하지만 품질 개선이 미미하다 → 삭제
- 복잡도를 추가하고 품질 개선이 명확하다 → 유지

## 프레임워크 2: 실용성 점검

실제 사용자가 일상적으로 이 스킬을 쓸 수 있는지 검증한다.

### 질문 목록

**입력 부담:**
- 사용자가 매번 제공해야 하는 정보가 3개 이하인가?
- 3개를 넘으면, 일부를 기본값으로 대체할 수 있는가?
- 첫 사용과 반복 사용의 입력량 차이가 있는가? (있어야 한다)

**출력 유용성:**
- 결과물을 받자마자 바로 쓸 수 있는가?
- 추가 편집이 필요하다면, 어느 부분이고 얼마나 걸리는가?
- 결과물의 형식이 사용자의 실제 작업 환경과 맞는가?
  (예: 인쇄용이어야 하는데 화면용으로 나온다면 실패)

**마찰 지점:**
- 워크플로우에서 "이건 번거로운데"라고 느낄 단계가 있는가?
- 그 번거로움이 품질을 위해 필수적인가?
- 필수적이지 않다면 제거한다. 필수적이라면 그 이유를 스킬에 명시한다.

### 판단 기준

- 입력이 너무 많다 → 기본값 추가 또는 단계 통합
- 출력을 바로 쓸 수 없다 → 형식 조정
- 마찰이 불필요하다 → 해당 단계 제거 또는 간소화

## 프레임워크 3: 차별화 점검

스킬이 실제로 AI의 기본 행동을 바꿨는지 검증한다.
이것이 가장 중요한 점검이다.

### 실행 순서

1. 단계 1의 baseline 결과물을 다시 연다
2. 현재 스킬로 같은 작업을 수행한다
3. 두 결과물을 나란히 놓고 비교한다

### 비교 항목

**구조 비교:**
- 전체 구성이 다른가?
- 섹션의 수, 순서, 역할이 다른가?
- 다르다면 → 통과. 같다면 → 단계 3의 금지 구조가 충분한지 재검토.

**접근 방식 비교:**
- 같은 정보를 다른 각도에서 다루는가?
- 우선순위가 다른가? (무엇을 먼저, 크게 다루는가)
- 다르다면 → 통과. 같다면 → 단계 2의 사고 아키텍처가 충분한지 재검토.

**표현 비교:**
- 금지 패턴 목록의 표현이 하나라도 남아 있는가?
- "AI가 쓴 느낌"이 드는 문장이 있는가?
- 없다면 → 통과. 있다면 → 금지 목록에 해당 표현 추가 후 재생성.

### 최종 판정

세 항목 모두 통과 → 단계 7로 진행.
하나라도 실패 → 실패 원인에 해당하는 단계로 돌아가 수정.

### 차별화
- 구조: [다름 / 같음 → 조치 내용]
- 접근 방식: [다름 / 같음 → 조치 내용]
- 금지 표현 잔존: [없음 / 있음 → 조치 내용]

### 최종 판정: [통과 / 재수정 필요 → 돌아갈 단계]
