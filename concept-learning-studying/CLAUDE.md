# 006_coding 프로젝트 설정

## 사용자
- 초등학교 교사, 코딩 중급
- 수업, 업무, 학습 전반에 코딩 활용

## 응답 규칙
- 한국어로 응답
- 코드 주석도 한국어
- 모르는 개념은 쉽게 풀어서 설명
- 코드 변경 시 "왜 이렇게 하는지" 함께 안내

## Skills 폴더
프로젝트 유형별 가이드는 워크스페이스의 `skills/` 와 전역 Codex 스킬 폴더 `~/.codex/skills/` 에 있을 수 있다.
해당 유형의 작업 시 관련 `SKILL.md` 또는 `Skill.md` 를 먼저 읽고 따를 것.
워크스페이스에 없더라도 전역 스킬이 있으면 사용할 수 있다.

현재 워크스페이스에서 확인된 스킬은 아래와 같다.

- `skills/01_cbi-orchestrator/SKILL.md` → CBI 전체 흐름 총괄. 랜덤 매칭 → 일반화 → 3층 질문까지 순서대로 진행
- `skills/02_cbi-curriculum-random-matching/SKILL.md` → 교육과정 JSON/TXT에서 학년·과목 기준 랜덤 단원 묶음 추출
- `skills/03_cbi-generalization-coach/SKILL.md` → 거시 1~2개 + 미시 5~7개 일반화 작성 코칭 및 루브릭 채점
- `skills/04_cbi-inquiry-3tier/SKILL.md` → 승인된 미시 일반화를 기반으로 사실적·개념적·논쟁적 질문 세트 설계
- `skills/edu-text-summarizer/edu-text-summarizer/Skill.md` → 교육학 텍스트를 고정 템플릿의 Markdown 요약 문서로 구조화
- `skills/edu-deep-talk/edu-deep-talk/Skill.md` → 교육학 텍스트를 바탕으로 심화 대화 후 교육과정 연결과 수업 설계안 생성
- `skills/frontend-slides/SKILL.md` → 애니메이션 중심의 단일 HTML 프레젠테이션 제작

스킬 사용 원칙:
- CBI 전체 설계 요청이면 `01_cbi-orchestrator` 를 우선 검토하고, 그 안에서 연결된 하위 스킬 순서를 따른다.
- CBI 일부 단계만 요청이면 해당 단일 스킬만 직접 사용한다.
- 교육학 독서 정리는 `edu-text-summarizer`, 읽은 내용을 수업 적용까지 대화로 확장하는 요청은 `edu-deep-talk` 을 사용한다.
- 발표 자료 제작 요청은 `frontend-slides` 를 우선 사용한다.
- 워크스페이스 스킬이 우선이며, 필요한 기능이 없을 때만 전역 스킬을 추가로 찾는다.

## 워크플로우

### 1. Plan 우선
- 3단계 이상이거나 구조적 판단이 필요한 작업은 반드시 Plan 모드 진입
- 방향이 틀렸을 때는 즉시 멈추고 재계획 — 억지로 밀어붙이지 않기
- 검증 단계도 Plan 모드로 설계 후 진행
- 모호한 부분은 시작 전에 명세로 정리

### 2. Subagent 활용
- 조사, 탐색, 병렬 분석은 서브에이전트에 위임해 메인 컨텍스트 보호
- 복잡한 문제일수록 서브에이전트를 적극 활용
- 서브에이전트 하나당 하나의 역할만 부여

### 3. 자기개선 루프
- 사용자 수정이 발생하면: `tasks/lessons.md` 에 패턴 기록
- 같은 실수를 반복하지 않도록 규칙화
- 세션 시작 시 관련 프로젝트의 lessons 검토

### 4. 완료 전 검증
- 작동이 확인되기 전까지 완료 처리 금지
- 변경 전후 동작 차이를 직접 확인
- "시니어 개발자가 승인할 코드인가?" 자문하기

### 5. 우아함 추구 (균형 있게)
- 비자명한 변경이라면 "더 우아한 방법이 있는가?" 점검
- 억지로 구현한 느낌이면: 가장 우아한 방법으로 재구현
- 단순하고 명백한 수정은 과도하게 고민하지 않기

### 6. 버그 자율 해결
- 버그 리포트를 받으면: 스스로 로그·에러를 추적해 해결
- 단, 해결 과정과 이유는 사용자가 이해할 수 있게 설명

---

## 태스크 관리

1. **계획 먼저**: `tasks/todo.md` 에 체크 가능한 항목으로 작성
2. **계획 검토**: 구현 시작 전 확인
3. **진행 추적**: 완료 항목은 즉시 체크
4. **변경 설명**: 각 단계마다 핵심 내용 요약
5. **결과 기록**: `tasks/todo.md` 에 리뷰 섹션 추가
6. **교훈 저장**: 수정 발생 후 `tasks/lessons.md` 업데이트

---

## 핵심 원칙

- **단순함 우선**: 변경은 최소한으로, 영향 범위를 좁게
- **근본 해결**: 임시방편 금지. 원인을 찾아 제대로 고치기
- **최소 영향**: 필요한 것만 건드리기. 버그를 새로 만들지 않기
