# PRD vs 참조문서 차이점 분석 보고서

> **비교 대상:**
> - PRD: `tasks/prd-vocab-bridge.md`
> - 참조 1: `proposal/proposal_v3.md` (통합 기획·개발 명세서)
> - 참조 2: `proposal/student_report_design.md` (리포트 시스템 설계서)
> - 참조 3~7: `proposal/Step1~5_세부계획서.md` (단계별 상세 기획)

> **리뷰 상태 범례:**
> - ✅ 리뷰완료 — 결정 완료, PRD에 반영됨
> - 🔄 리뷰진행중 — 논의 시작했으나 미완료
> - ⬜ 리뷰미진행 — 아직 검토하지 않음

---

## 1. 수용 기준 — 90개 단어 세트 ✅ 리뷰완료

| 항목 | proposal_v3 | PRD |
|------|-------------|-----|
| 1차 출시 어휘 수 | 수용 기준에 **"90개 단어 세트 로딩/학습 정상"** 명시 | 제외 범위에 **"90개 단어 전체 콘텐츠 입력 (1차 출시는 Step별 지정 단어 세트)"** 명시 |

**결정사항:**
- 단어는 90개에 국한되지 않고, 교사가 계속 추가하는 구조
- **10개 단어 = 1 퀴즈 사이클** (Step 1 → Step 6 전체 순회)
- 1차 출시: 개발자가 데이터 세팅, 구조만 퀴즈 사이클 기반으로 설계
- 2차: 교사 단어 추가 UI

**PRD 반영 내역:**
- 개요: "90개 학습도구어" 제거 → 퀴즈 사이클 구조 설명 추가
- US-004: 퀴즈 사이클 기반 데이터 구조로 재정의 (`cycles` 배열)
- US-015-S: learning_records에 `cycle_id` 필드 추가
- 제외 범위: "교사 단어 추가/편집 UI (2차 이관)"으로 변경
- FR-16, FR-16a 신규 추가
- 기술 고려사항: 퀴즈 사이클 라우팅 설명 추가, `vocabData.js` → `.json` 통일
- 1차 수용 기준: 퀴즈 사이클 / 복수 사이클 전환 항목 추가
- 미결 질문 #1: 사이클 내 단어 통일 문제 추가

## 2. 개발 우선순위 — 배포 최우선 vs 인증 최우선 ✅ 리뷰완료

| 항목 | proposal_v3 (§11.1) | PRD |
|------|----------------------|-----|
| 최우선 | 인증/권한 → 학생 등록 → 학습 1~6단계 → 채점 → 리포트 | **배포·호스팅(Gate 0)** → 인증 → 데이터·학습 → 리포트 |

**결정사항:** 배포·호스팅 최우선은 교사가 의도적으로 PRD에 추가한 필수 요구사항이다. proposal_v3에 없었으나, 실제 운영에 반드시 필요하므로 PRD 기준이 정본이다. 수정 불필요.

## 3. 데이터 모델 — words 컬렉션 구조 차이 ✅ 리뷰완료

| 필드 | proposal_v3 (§9.2) | PRD (US-004 vocabData.json) |
|------|---------------------|----------------------------|
| ID 필드 | `word_id: "W001"` | `id: "W001"` |
| 다국어 번역 | 없음 | `zh`, `ru` 필드 추가 |
| 예문 | `example_1`, `example_2`, `example_3` (개별 필드) | `examples: [...]` (배열) |
| 시각 자료 | `image_prompt` | `icon` (lucide-react 컴포넌트명) + `color` |
| 관련어 | `related_words: [...]` | `relatedWords: []`, `unrelatedWords: []` (비관련어 추가) |
| Step 4 데이터 | `l4_draft: "정답:설명 \| 보기:..."` (평문 형식) | `step4: { dictionaryForm, targetWord, syllables, sentencePre, sentencePost, distractors }` (구조화 객체) |
| Step 5 데이터 | `l5_draft: "정답문장:... \| 카드:..."` (평문 형식) | `step5: { chunks, targetIndex, vocabDistractor, hints, fullDistractors }` (구조화 객체) |

**결정사항:** PRD의 구조화된 데이터 모델이 proposal_v3보다 진보된 형태이므로 PRD 기준이 정본이다. 수정 불필요.

## 4. 데이터 모델 — learning_records 구조 차이 ⬜ 리뷰미진행

| 필드 | proposal_v3 (§9.3) / student_report_design (§8.1) | PRD (US-015-S) |
|------|---------------------------------------------------|----------------|
| stage_results 범위 | stage 1~5 모두 포함 | Step 1은 unknownDeck 단어 목록만 별도 기록, Step6은 총점만 기록 |
| time_spent | student_report_design에 `time_spent` 필드 포함 | **없음** |
| completed | student_report_design에 `completed: true` 필드 포함 | **없음** |
| 저장 트리거 | 명시 없음 (암묵적으로 모든 학습 저장) | `min_save_step` 이상 완료 시에만 최초 저장, 이후 누적 업데이트 |

**분석:** PRD는 `time_spent`와 `completed` 필드를 제거했고, `min_save_step` 기반 조건부 저장 로직을 도입했다. student_report_design의 `time_spent`를 활용한 리포트 지표(예: `avg_time_min`)를 PRD가 지원하지 않게 된다.

## 5. 데이터 모델 — intervention_logs ID 형식 ⬜ 리뷰미진행

| 항목 | proposal_v3 (§9.4) / student_report_design (§8.2) | PRD (US-019) |
|------|---------------------------------------------------|--------------|
| intervention_id 형식 | `"INT_001"` / `"INT_20260213_S001_01"` | `"INT_날짜_학생ID_순번"` |

**분석:** proposal_v3는 단순 순번("INT_001"), student_report_design은 날짜+학생ID 포함("INT_20260213_S001_01"), PRD는 날짜+학생ID 패턴을 명시. student_report_design과 PRD는 동일하나 proposal_v3와 차이가 있다.

## 7. 학습 기록 저장 기준 — 고정 vs 설정 가능 ⬜ 리뷰미진행

| 항목 | student_report_design (§5.2) | PRD (US-015) |
|------|------------------------------|--------------|
| 중간 종료 유효 기준 | **Step 3 고정** ("1,2단계 종료시 무효") | 교사가 **Step 2~5 중 선택 가능** (기본값 Step 3) |

**분석:** student_report_design은 Step 3 미만 완료 시 무효로 고정 규칙을 제시했으나, PRD는 이를 교사가 대시보드에서 설정할 수 있도록 확장했다.

## 8. 리포트 레벨 체계 ⬜ 리뷰미진행

| 항목 | student_report_design (§2) | PRD |
|------|---------------------------|-----|
| 레벨 1 (실시간) | 별도 리포트 레벨로 정의 (필수 아님) | "교사 대시보드"(US-016)로 분류, 리포트 레벨에서 제외 |
| 레벨 2 (주간 개인) | 리포트 레벨 2 | US-017: "개인 주간 리포트 (레벨 2)" — 일치 |
| 레벨 3 (월간 그룹) | 리포트 레벨 3 | US-018: "월간 그룹 리포트 (레벨 3)" — 일치 |

**분석:** PRD는 실시간 현황을 "리포트"가 아닌 "대시보드"로 재분류했다. 기능은 동일하나 구분 체계가 다르다.

## 12. 오류율 만점 기준 ⬜ 리뷰미진행

| 항목 | student_report_design (§4.2) | PRD (US-015-S) |
|------|------------------------------|----------------|
| 만점 정의 | "단어 1개(5단계) 만점: 10점" (단어 단위 5단계 합산) | Step별 만점이 상이 (Step 3: 18점, Step 4: 16점, Step 5: 30점 등) |

**분석:** student_report_design은 단어 1개에 대해 5개 단계 × 2점 = 10점 만점으로 오류율을 계산하지만, PRD는 Step 단위로 만점이 다르다. 오류율 계산 공식은 동일(`(1 - 획득/만점) × 100`)하나, "만점"의 단위가 단어 기준 vs Step 기준으로 다르다.

## 14. Step 2 — TTS 힌트 점수 감점 정책 모호 ⬜ 리뷰미진행

| 항목 | Step2_세부계획서 | PRD (US-009) |
|------|------------------|--------------|
| 슬롯 TTS 힌트 | "슬롯 탭 시 문맥 힌트 TTS 재생"을 기본 상호작용으로 설명 | "빈 슬롯 탭 시 해당 단어의 문맥 힌트 문장을 TTS로 재생" + "힌트 없이 정답 2점, TTS 힌트 후 정답 1점" |

**분석:** 세부계획서는 슬롯 탭 TTS를 기본 인터랙션으로 설명하지만, PRD는 이 TTS 재생을 "힌트 사용"으로 간주하여 점수를 감점한다. 학생이 자연스럽게 슬롯을 탭하면 의도치 않게 감점될 수 있으므로 UX 관점에서 검토가 필요하다.

## 18. Step 3 — 관련어/비관련어 풀 크기 ⬜ 리뷰미진행

| 항목 | Step3_세부계획서 (§2.1) | PRD (US-004 vocabData) |
|------|-------------------------|------------------------|
| Good Pool | 관련어 **10개** | `relatedWords: []` (개수 미정) |
| Bad Pool | 비관련어 **5개** | `unrelatedWords: []` (개수 미정) |

**분석:** Step3_세부계획서는 Good Pool 10개, Bad Pool 5개를 명시했으나, PRD의 vocabData 구조에서는 배열 크기를 규정하지 않았다. 세부계획서의 어휘 풀 표를 보면 실제로는 Good 5개, Bad 5개로 예시되어 있어 세부계획서 내부에서도 불일치가 있다(본문 10/5 vs 표 5/5).

## 19. proposal_v3 세션 규칙 미반영 ⬜ 리뷰미진행

| 항목 | proposal_v3 (§6.1) | PRD |
